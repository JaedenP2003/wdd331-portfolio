The interpolate-size property

CSS can only animate between two concrete values. A height of auto is not a number, it is an instruction to work out the height from the content, so the browser has no midpoint to calculate. The property interpolate-size lets the browser resolve keywords like auto, min-content and max-content to real numbers before animating.

You opt in with interpolate-size: allow-keywords, and the usual place to set it is on :root, because the property inherits and every element on the page then gets the behavior.

Why max-height is a poor fit

The old workaround animates max-height to a large number, because a number can be interpolated. The trouble is that the number is a guess. If the content is 150px tall but you animate to 1000px, the panel is fully open after about 15 percent of the time, then nothing visible happens for the rest of the transition.

Easing suffers too. The curve is applied to the whole 1000px distance, not the 150px that is actually visible, so the motion feels wrong. Closing is worse, because the panel waits before it starts to shrink.

JavaScript and progressive enhancement

This pattern is built in layers. Native details gives you open and closed state in every browser. CSS adds the animation where it is supported. In a browser without interpolate-size, the panels still work and simply open instantly.

If you need the animation everywhere, a small script can measure the panel's scrollHeight and set a pixel height. Wrap it in CSS.supports() so it only runs where the property is missing, otherwise the inline height would fight the CSS.

Respecting prefers-reduced-motion

Some people get dizzy or distracted by motion, and they say so with an operating system setting. The prefers-reduced-motion: reduce media query lets the page listen. In this demo it turns off the height transition and the arrow rotation, so the panels open instantly for those visitors.

It is a small block of CSS, and it belongs in every animated disclosure pattern.

max-height: 100rem

Open the max-height panel

This content is only about 100px tall, but the transition travels toward 1000px. The panel is fully open long before the animation ends, so it looks like a quick pop followed by a pause. On closing, it hovers at full size before it starts to shrink.

height: auto

Open the height: auto panel

This content is only about 100px tall, and the transition travels exactly 100px, from zero to the content's real height. The easing curve applies to the distance you can actually see, and the motion finishes exactly when the panel is fully open.

What I found while building this

The course page animates a .panel inside the details element. In current Chrome that pattern opens with a jump and snaps shut, because a closed details stops rendering its content immediately, so the transition on the panel is never seen.

Chrome now wraps that content in a ::details-content box. Animating the box with height and content-visibility fixes both directions. The panel itself then stops animating, because two nested height transitions fight each other. Use the second checkbox above to switch between the two.
